# Notes

Gotchas, oddities and findings that are not open issues ([`ISSUES.md`](ISSUES.md)). 
Read this before a live-model session — the provider and harness quirks below cost real time to rediscover.

## simple-code-indexer
- **Workspace walks must prune ignored dirs (`os.walk` + `dirnames[:]`), never `Path.rglob("*")`** — rglob descends into `.venv` (tens of thousands of files) over the Docker Desktop bind mount, which made the startup reconcile take so long that the phase-2 probe timed out with only 6 files indexed. `indexer.iter_workspace_files` prunes; keep it that way if refactoring.
- **The watcher is now one recursive watch on the workspace root** (2026-11-10). watchdog maps `recursive=True` to a single `ReadDirectoryChangesW(..., bWatchSubtree=TRUE)` and one emitter thread; `schedule()` itself does no tree walk. The old one-watch-per-directory design created one thread and handle per directory (a Visual Studio workspace reached 3,227 threads — ISS-7), so do not reintroduce it. watchdog **does** walk a newly created directory to synthesize sub-events (`generate_sub_created_events`), so creating a huge tree (e.g. `.venv` during `uv sync`) while the server runs can briefly delay event dispatch; the sweep is the backstop. **Every handler drops `IGNORE_DIRS`, the active log file, and `.gitignore` matches silently before any event logging** (`watcher.build_handler.excluded`). Logging first made a `sci.log` write log to `sci.log` and re-trigger itself indefinitely (ISS-9, fixed 2026-11-11); keep all event logging behind `excluded()`.
- **`.gitignore` support is workspace-local and layered** (`ignore.IgnoreRules`, pathspec): root and nested `.gitignore` files are honored, the deeper file wins, and matching is case-insensitive on Windows (git's `core.ignorecase` default). Every **ancestor directory is checked before the path itself**, so a nested `!keep.py` cannot re-include a file under an excluded parent directory (matching git's rule); per-file checks such as `index_one_file` must go through `IgnoreRules`, not only the `IGNORE_DIRS` test. `.git/info/exclude`, `core.excludesfile`, and a parent repo's `.gitignore` above `WORKSPACE_ROOT` are deliberately ignored. `IGNORE_DIRS` is still applied first and remains the fallback. A sweep drops rows for files that become ignored (they disappear from the walk), and a `.gitignore` edit enqueues a sweep; `get_status.ignored_dirs`/`ignored_files` report the last pass.
- MCP SDK is **2.x** (installed `mcp==2.3.0`): the TDD's decorator API (`@server.list_tools`) no longer exists — handlers are constructor kwargs (`Server(name, on_list_tools=…, on_call_tool=…)`), and models are constructed with **snake_case** field names (`input_schema=`, `is_error=`), serialized camelCase on the wire.
- Ruff 0.17 formats Python code blocks inside `*.md` and wanted to rewrite `docs/tdd.md` (the build contract) — `pyproject.toml` excludes `*.md` from ruff.
- **llama.cpp embedding endpoint size limits**: the compose file sets `LLAMA_ARG_UBATCH=2048`; an input larger than the physical batch still returns HTTP 500 (`input (N tokens) is too large to process`). The env names matter: this build reads `LLAMA_ARG_BATCH`/`LLAMA_ARG_UBATCH`, not `..._SIZE`. With the wrong names llama.cpp ignores them and resets n_batch/n_ubatch to 512 (and rejects ~560-token inputs). `embed.embed_texts` still splits oversized texts into ≤1200-char pieces and mean-pools the piece vectors — keep that guard for older containers.
- Loopback connections to closed ports on this Windows host take **2–4 s to fail** (not instant RST) — unit tests must not hit the network; `test_indexer`/`test_watcher` stub `embed.embed_texts`, and `embed.py` caps connect timeout at 1 s.
- **Plugin allowlist needs filename matching**: `Path("CMakeLists.txt").suffix == ".txt"` and `Path("Dockerfile").suffix == ""` — `path.suffix` alone cannot express those, hence `Settings.allowed_filenames` + `config.is_allowed`. `Path(".vimrc").suffix` is also empty; `.vimrc` is registered as a FILENAME (and `.vimrc` as an extension for `foo.vimrc`).
- **tree-sitter-language-pack downloads grammars on demand**: on a fresh machine only `['cpp','python']` are local until `get_parser` fetches the rest. Server startup prefetches in a daemon thread (`PREFETCH_GRAMMARS=0` to disable); offline first-use falls back to the regex symbol scan. Unit tests that parse non-python/cpp languages must stub `parse._parser`.
- **Plugin user override is silent** (debug log only): a `plugins/cpp.py` replaces the builtin by `NAME` and frees/reclaims its extensions — redeclare the original extensions in the user plugin or `.cpp`/`.py` stop matching. `detect_language` returns the plugin `NAME` (`c_sharp`), not the pack grammar (`csharp`).
- **Data/doc formats are deliberately not in the builtin set** (json, yaml, toml, xml, csv, markdown, plaintext, rst, latex, regex) — the original registry's 47 entries ship as 36 builtin plugins (those 10 skipped, matlab omitted because `.m` is owned by objc).
- **`uvx --from <repo> simple-code-indexer` preserves the process cwd** (verified) — that is the whole mechanism behind the workspace inference. The *first* launch after a source change rebuilds and installs into a cached environment (~5 s; ~0.3 s warm), so a slow first `mimo mcp list` is not a hang. The ephemeral env is separate from the repo's `.venv`.
- **Workspace = `Path.cwd().resolve()` unless `WORKSPACE_ROOT` is set**, and `get_status.workspace`/`collection` are the only way to confirm what a live harness really spawned: MiMoCode ships as a compiled binary, so its spawn code cannot be inspected. A harness that spawns servers from elsewhere silently indexes *that* directory instead. **An inferred workspace that is the user's home directory is refused** (`config._reject_home_workspace`, clean `ConfigError` exit): the OpenCode desktop app runs its global MCP entries with cwd = `C:\Users\KJ` for the home-screen "directory", which created a 32 MB `~/.simple-ci/index.db` that looked like the global index. Sessions opened on a project get the project cwd (verified: `VideoDeduper/.simple-ci`) and are unaffected; an explicit `WORKSPACE_ROOT` still opts in to indexing home.
- **Collection names are case-folded path hashes**: on a case-sensitive filesystem `/x/App` and `/x/app` collapse onto one collection (deliberate — it keeps Windows drive-letter case from splitting one project in two). Slug: non-alphanumerics → `-`, capped at 32 chars, empty → `root`.
- **`meta.qdrant_url` + `meta.qdrant_collection` bind an index DB to exactly one endpoint and collection.** Any mismatch — *including rows written before those keys existed* — drops every row so the startup reconcile re-embeds them; points left in the previous collection are orphaned (delete by hand). The retired global `code_index_2560` is still sitting in Qdrant.
- **`registry.default_user_plugin_dirs()` now resolves the workspace like settings do** (`WORKSPACE_ROOT` else cwd). It used to hardcode `/workspace`, which would have loaded user plugins from a directory that does not exist on this host.
- **Machine state from the Docker era**: `.pytest_cache/` in this repo and `%TEMP%\pytest-of-KJ` are unreadable and undeletable for the current user (container root created them over the bind mount). `uv run pytest` fails on every `tmp_path` test until an elevated shell removes them; the workaround is `uv run pytest -p no:cacheprovider --basetemp <writable dir>`.
- **First use of a workspace collection is a three-way race**: the service-probe thread, the index writer, and a semantic search all call `ensure_collection` at once. Unguarded check-then-create answered `409 Conflict` to the losers, and because indexing is fail-soft that silently cost the workspace *all* its vectors. `ensure_collection` is now serialized in-process and re-checks existence when a create fails, so a create it lost to another process is fine. Reproduced 2026-10-18 while verifying two-workspace isolation; the integration test only passed once this was fixed.
- **Startup takes an OS advisory lock on `.simple-ci/index.db.lock`**: a second server process for the same workspace logs `another simple-code-indexer already owns …` and exits, enforcing the single-writer invariant (ADR-0004) under host spawning. The lock is `msvcrt.locking` / `fcntl.flock`, released by the OS on process death, so the leftover lock file on disk is harmless.
- **Every sweep re-embeds chunks whose `embedding_state.status != 'ok'`** (or that have no row), independent of the file hash/mtime short circuits. It stops at the first failing file, so a downed embed endpoint costs one retry per sweep rather than one per pending file; successful chunks are never re-embedded.
- **Several open workspaces share one embedding endpoint** (one server per workspace, ADR-0004). `embed.py` splits each request into ≤16-input batches, keeps at most two posts in flight per process, and retries with full-jitter exponential backoff — request-level back-pressure, not an endpoint-wide limiter. N workspaces still multiply the load; `get_status.pending_embeddings` and semantic `search_code.ready` show when vectors are still catching up.
- **The MCP probes drain the server's stderr on a thread** (`tests/mcp_probe._spawn`, shared with `tests/live_watch_probe.py`). The server logs INFO per indexed file and per tool call; an unread `stderr=subprocess.PIPE` fills and blocks it inside a log write. `PROBE_TIMEOUT` (default 180 s) bounds the run. Do not reintroduce a bare `stderr=subprocess.PIPE` there.
- **`ensure_collection` validates the existing collection's vector size against `EMBED_DIM`** (and rejects named-vector collections): a mismatch raises `QdrantUnavailable` with both sizes — indexing stays fail-soft (`qdrant_ok: false` in `get_status`) but no longer silently accepts a vectorless workspace.
- **A semantic query is nearest-chunk, not a lexical match**: asking a workspace for a symbol it does not contain still returns its own closest chunk. Isolation tests must assert "every hit comes from this workspace", never "an unrelated query returns nothing".
- **`setup.py` is a launcher, not a setuptools script** — `build-backend = "uv_build"` ignores it. It runs `uv sync` and then calls the project venv's interpreter directly. Do **not** switch that to `uv run --project <repo>`: `--project` changes the working directory, and the wizard must configure the caller's cwd (the project being indexed).
- **Config discovery leaks into tests unless disabled**: the autouse fixture in `tests/conftest.py` sets `SIMPLE_CI_CONFIG=none`. `test_multi_workspace_isolation` spawns a child process, so it also sets the variable explicitly (a monkeypatch is not inherited).
- **`uv run` re-syncs after every source edit**, which is why `python setup.py` prints the build/sync lines each run; this is not a hang.
- **Harness path expansion takes an explicit home**: `HarnessSpec.candidates(..., home=...)` exists so the wizard can write to the fake home in tests (and respects `Path.home()` in production). Do not regress to bare `expanduser()`.
- **Command Code detection must not use the `cmd` binary** — on Windows that is the shell, so every machine would look like it has Command Code installed. Its plugin only checks `~/.commandcode`.
- **JSONC comments are lost on rewrite**: `harnesses/_json.py` strips `//` and `/* */` to parse OpenCode files, then writes strict JSON. `write.install` backs the file up and refuses to write a document it cannot parse; keep both behaviors.
- **Codex config is merged with marker comments** (`# >>> simple-code-indexer >>>`), not a TOML round-trip: `tomllib` cannot write, and rewriting would destroy user comments/order.
- **Managed services block the startup path** (by design) for up to `startup_timeout_s`; they are fail-soft afterwards (`get_status.services`). Harness configs from the wizard use `timeout: 120000` because of this.
- **FAISS is the default vector store** (`vector_store: faiss|qdrant`, `VECTOR_STORE` wins). The key is a top-level *scalar*, so read it with `configfile.get_str`, never `get_mapping`. A config with no `vector_store` key but a non-empty `qdrant:` section resolves to `qdrant`; an empty `qdrant: {}` does not.
- **FAISS label ids must never be recycled.** `vector_labels` rows are deleted (file removed, identity invalidated), so `MAX(label)+1` alone would eventually reuse an id; `meta.vector_label_seq` is the monotonic source. A reused id could attach an old vector left in `vectors.faiss` by a crash to a new chunk.
- **One lock covers the FAISS index *and* the `vector_labels` mapping** (`faiss_store._lock`). Upsert allocates + marks labels dirty, then removes-adds under that lock; `flush` writes the file and clears the dirty flags under the same lock. Splitting either side reintroduces the "flag cleared for a vector not in the file" race.
- **An invalidated identity resets FAISS by writing an empty index immediately** (`faiss_store.reset`), not just in memory: `server._run` calls `ensure_ready` right after, which would happily reload the stale file — and the label sequence was not reset, so colliding ids are possible if the old file survives. A failed reset unlinks the file as a fallback.
- **`embedding_state.qdrant_point_id` is migrated to `vector_id`** in `db.ensure_schema` via a guarded `ALTER TABLE ... RENAME COLUMN`; the `NOT NULL` and no-rebuild behaviour are deliberate.
- **FAISS write paths call `db.ensure_schema` themselves** (`upsert`, `delete_by_path`, `reconcile`, `flush`). The store is usable before the server's startup `ensure_schema`; search is read-only and assumes the table exists.
- **`faiss_store` imports numpy at module load and faiss lazily**; `vector_store.py` lazy-imports `faiss_store` so the Qdrant-only path never pays for either. `faiss.loader` logs its AVX2 probe to stderr on first use.
- **The status payload is a breaking change**: `qdrant_ok`/`collection` are gone, replaced by `vector_store`, `vector_store_ok`, `vector_index` (the FAISS path or the Qdrant collection). `tests/mcp_probe.py` and `tests/test_multi_workspace_isolation.py` were updated to match.
- **`tests/test_multi_workspace_isolation.py` now needs only the embedding endpoint** (it forces `VECTOR_STORE=faiss`), not Qdrant. `tests/service_probe.py` treats Qdrant as optional unless `VECTOR_STORE=qdrant`.
- **`test_indexer`'s fixture sets `vector_store="qdrant"`** because those tests patch `qdrant_store.upsert_chunks`. The patched function must return a list of ids (the router now propagates them into `embedding_state.vector_id`); returning `None` raises inside `zip`.
- **Global assets live under `~/.simple-ci/docker/` and `~/.simple-ci/model/`**: `docker-compose.yml` and the copied `gpu_init.sh` sit next to each other, and the compose model mount is the relative `../model:/models:ro`. Keep the relative path (the compose file is portable across machines); do not reintroduce an absolute host path like the original template's `D:/LocalLLM/models`.
- **The compose template ships inside the package** (`src/simple_code_indexer/setup_wizard/templates/`). `uv_build` includes everything under the module root, so no `package-data` config is needed — but `docker_template/` at the repo root would NOT ship via `uvx`; that is why it moved.
- **The llama.cpp image tag encodes the backend**: `server` (CPU), `server-cuda`, `server-rocm`, `server-intel` (SYCL). Detection prefers `nvidia-smi -L`, then Windows `Win32_VideoController`, then Linux `/sys/class/drm/card*/device/vendor` (`0x10de`/`0x1002`/`0x8086`); `--gpu` overrides. On this host Docker already exposes `nvidia-container-runtime`, so `nvidia_runtime_ready` skips `gpu_init.sh`.
- **`LLAMA_ARG_ALIAS` pins the OpenAI `model` id** to the catalog's `api_model`; without it llama.cpp reports the GGUF `general.name`, and a config/wizard probe can disagree with the served name.
- **Compose names its own containers (`<project>-<service>-1`); never hardcode the name.** The packaged compose file pins a top-level `name: simple-ci` (not `container_name`), and `write_compose` rewrites that key unconditionally, so the real containers are `simple-ci-embed-1` / `simple-ci-qdrant-1`. Resolve the name with `provision.compose_container_name` (asks `docker compose ps`, then falls back to the derived name) and store *that* in the config. A hand-edited file with `name: simple-ci-embed` creates `simple-ci-embed-embed-1`; the next wizard run rewrites the project and `_compose_start` offers to stop the old container when it still holds the port. The server side mirrors this: `services._compose_container_name` asks `docker compose ps -a --format {{.Name}}` after `compose up`, so a stale `service.container` in an old config no longer sends the readiness wait to a name that does not exist.
- **`SO_REUSEADDR` is unusable for "is this port free?" on Windows**: with it set, `bind()` succeeded on a port Docker already published, so `available_port` reported 8080 free, `docker compose up` then failed with "address already in use", and the wizard aborted after creating the container. `available_port`/`port_is_free` bind without it, and `port_is_free` also counts any running container publishing the port as taken (`available_port_for_docker`).
- **Loopback URLs must use `127.0.0.1`, not `localhost`**: Docker publishes `127.0.0.1:<port>` (IPv4-only) while `localhost` resolves `::1` first on Windows; each dead-IPv6 attempt stalls for the connect timeout (~1.1 s), which made the wizard look hung and added ~1 s to *every* embedding request. `config.ipv4_loopback` rewrites loopback URLs; the wizard probes, `services._probe`, and `embed._post_embeddings` all use it. Any new runtime HTTP call site must normalise too (`localhost` in the stored config is intentional and human-friendly).
- **Every service wait prints a heartbeat**: `provision.wait_until(..., output=..., progress_every=15)` prints `still waiting (Ns of Ts)`; a silent 2–5 minute wait is indistinguishable from a hang (the original "setup just hangs" report). Pass `output=self.prompts.say` for every wait that can outlast the model load.
- **The initial embedding menu lists every Docker container**, not just embedding-looking ones: only running containers get a `(running)` suffix, and exited state/model names are deliberately not shown. `--yes` defaults to the catalog download, never the first container, so a non-interactive run cannot start an arbitrary container. The download sub-menu marks catalog GGUFs already in `~/.simple-ci/model/` with `(downloaded)` (selecting one is a no-op download). The old `list_embedding_containers`/`_EMBED_NEEDLES` filter was deleted with the flat menu.
- **Query vs document prompts are asymmetric by design**: EmbeddingGemma 2 gets `task: code retrieval | query: ...` on queries and `title: <relative path> | text: ...` on chunks; Qwen3-Embedding gets only the `Instruct: ...\nQuery: ...` line. `embed_texts` stays raw for probes. `embed_fingerprint` now hashes the document prefix **and** the chunker profile, so changing either one invalidates the FAISS identity / derived Qdrant collection and re-embeds; changing only the query prompt does not.
- **Semantic retrieval is chunk-shape bound on EmbeddingGemma 2 — the old 80-line chunks were too coarse (ISS-5, fixed 2026-11-10).** `parse.chunk_source` now emits 30-line windows with 15-line overlap (`CHUNK_LINES`/`CHUNK_CHARS`/`CHUNK_OVERLAP_LINES`; `CHUNKER_VERSION` feeds `embedding_fingerprint`). On the 42-query `tests/retrieval_queries.json` set this moved R@1 0.667→0.786, R@5 0.952→1.000, R@10 0.976→1.000, MRR 0.771→0.877, nDCG@10 0.746→0.870, and put the pruning loop (`indexer.py:106-135`) at rank **1** for the ISS-5 query (before: `indexer.py` rank 4 and the pruning chunk outside the top 50). **Known model defect:** this model cannot bridge a natural-language query to unannotated code the way it matches prose. Direct cosine probes: the whole `iter_workspace_files` function scores 0.68, the bare `os.walk` pruning loop 0.80, the function docstring alone 0.79, and a synthetic "skip virtualenv and cache directories" summary 0.85, while unrelated file-head docstrings (`harnesses/__init__.py` 1-60, `watcher.py` 1-56) score 0.75-0.78. Container and prompts are correct per the model card (BF16, mean pooling, `task: code retrieval` + `title: … | text:`), so do not "fix" pooling. Other strategies all failed to surface the pruning chunk: 40/120-line windows, 60-line overlap, symbol-boundary chunks, path/symbol headers, and dropping the document prefix (symbol-aware chunks made it worse, rank 27). The model's useful retrieval unit is ~500-1000 chars of code; keep chunks focused. The throwaway harness and per-variant results live in `artifacts/chunk-exp/` (gitignored).
- **Overlapping chunks are deduped at query time** (`server._semantic_hits`): 30x15 windows overlap 50%, so it fetches `limit * 3` vector hits and drops a hit whose line span overlaps a higher-ranked hit from the same file. Without that, a semantic top-10 collapses to ~4.8 distinct files; with it, ~6.1 (the non-overlapping baseline was ~7.1). Do not remove the dedupe while the chunker overlaps.
- **The 1200-char embed-side split is nearly a no-op with mean pooling**: `embed_texts` still splits oversized inputs and mean-pools the piece vectors, but whole-vs-split cosine differed by <0.001 on 1.5-3.5 KB chunks (the mean of piece means is the whole-text token mean). Keep the guard for small-batch llama.cpp builds, but do not treat `_SAFE_CHARS` as a retrieval lever — chunking is.
- **Config is global only**: `configfile.config_paths` returns `~/.simple-ci/config.yaml` (or the `SIMPLE_CI_CONFIG` override), never the workspace file. The wizard migrates a legacy `<workspace>/.simple-ci/config.yaml` into the global file and deletes it. `load_layered_config`/`merge_configs` still exist for one-file parsing and the migration. `get_status.config_files` has 0 or 1 entries.
- **Menus use questionary, not simple-term-menu**: `simple-term-menu` imports `termios` at module load and raises `NotImplementedError` on Windows (its README says Linux/macOS only). `setup_wizard/prompts.py` keeps a numbered `input()` fallback for non-TTY runs and `SIMPLE_CI_NO_TUI=1`; the autouse test fixture sets it. `questionary.select(default=...)` wants a `Choice` (or a matching value), not a title string — pass `choices[default]`. `select()` also raises `ValueError` when `use_jk_keys` and `use_search_filter` are both true (j/k can be a prefix character) — `ask_choice` sets `use_jk_keys=not search`.
- **The installed copy is the harness target**: `setup_wizard/install.py` copies the working tree (including `.git` on the first install) to `%APPDATA%/simple-code-indexer` / `~/Library/Application Support/...` / `$XDG_DATA_HOME/...`, excluding `.venv`, caches, `artifacts/`, and `.simple-ci/`. Harness entries are `uv run --project <install> --no-sync python <install>/run_server.py`; `--no-sync` keeps the launch fast and lets the launcher own dependency syncs. Re-running setup refreshes the copy but preserves the installed `.git`. Changing `--install-dir` copies to the new target, then deletes the previously **recorded** copy (prompted, default yes; `--yes` takes the default; fail-soft, and skipped when the old path is the checkout or has no `run_server.py`), so `--uninstall` cannot leave an orphan behind.
- **`setup.py --install-only` copies the working tree and nothing else**: no prompts, config, services, harness entries, or `uv sync` of the copy (setup.py still syncs the checkout as its normal bootstrap). It preserves the installed copy's existing `.git`/`.venv`, so it is for refreshing an install — a copy without a `.venv` is not launchable until a full `setup.py` run syncs it. A `.venv` that exists but predates a new dependency is equally broken (the 2026-11-10 run got `ModuleNotFoundError: pathspec` from the installed launcher); run `uv sync --project <install>` after `--install-only` whenever `pyproject.toml`/`uv.lock` changed.
- **`run_server.py` pulls before importing the server**: `git pull --ff-only --autostash` (20 s bound), then `uv sync` only when `HEAD` moved, then `simple_code_indexer.server.main()` with cwd untouched. All failures are stderr-only and fail-soft; `SIMPLE_CI_GIT_PULL=0` disables the pull. The harness entry wraps it in `uv run --project <install> --no-sync python …`; `--project` **preserves** the caller's cwd (verified), while `--directory` changes it — never use `--directory` or a bare `uv run` here, because workspace inference depends on cwd. `git pull` on a dirty copy may leave the autostash unapplied on conflict; the tree stays at upstream and the next launch still works.
- **Harness paths were corrected to the 2026 clients**: OpenCode V2 nests servers under `mcp.servers` (the JSON helper supports dotted root keys); MiMo tries `~/.config/mimocode/{mimocode,config}.json`, `%APPDATA%/mimocode`, then legacy `~/.mimocode`; Windsurf prefers `~/.config/devin/mcp_config.json` with the legacy Codeium path as fallback; Codex emits `startup_timeout_sec = 120`; VS Code no longer offers `~/.vscode/mcp.json` as a global candidate.
- **The Cline builtin harness was removed (2026-11-08)**: the end-to-end run found `~/.cline/data/settings/cline_mcp_settings.json` gone after the Cline desktop app restarted — the wizard's entry did not survive there, and Cline never listed the server. `harnesses/cline.py` is deleted rather than patched; re-add it only with a verified path and lifecycle for the current Cline build.
- **OpenCode keeps MCP servers alive while its background service runs**: `opencode-cli serve --service` outlived the desktop UI, so the server's stdin never closed and it kept sweeping (two sessions → two servers; one was indexing `VideoDeduper` with a 300 MB index). Closing the UI is not enough to stop the server — the service must exit or the process tree must be killed. A venv-python launch also appears as **two** processes (uv's 274 KB trampoline spawns the base interpreter), and the `uv run` entry adds the uv launcher on top, so count servers by their `index.db` lock, not by `python.exe`.
- **OpenCode v2.2.5's service parent decides whether the watchdog can see the UI close** (verified 2026-11-10): when the desktop UI starts the service, the chain is `OpenCode.exe → opencode-cli serve --service → uv.exe → venv trampoline → server`; `parent_watch` watches all four and closing the UI stopped the server within ~2 s even though the service itself survived. A service started from a shell (`opencode service start`) has a dead parent, so the chain stops at the service and the UI is invisible to the watchdog. **The same happens when a later UI reuses a service started by an earlier UI**: the 21:37 run's service 427588 was started by UI 489696 (dead by then); the new UI was a sibling, the watchdog list stopped at the service, and the server survived the UI close (ISS-10). `opencode service stop` kills its MCP children (no `shutting down`/`workspace lock released` lines), while a clean stdin close still shuts the server down normally. `opencode mcp list` printed "No MCP servers configured" immediately after `service start`; re-running it (e.g. with `--print-logs --log-level debug`) read the config and reported `✓ simple-code-indexer connected` — treat the first result as a service warm-up race, not a missing entry. A `setup.py` re-run rewrites the OpenCode entry (and drops manual `environment` keys), so re-check/pin `SIMPLE_CI_GIT_PULL=0` after any reinstall when testing the working tree.
- **The existing Qwen3-4B container was created with `LLAMA_ARG_POOLING=mean`**; after recreating it with `last` on 2026-11-07, retrieval jumped (R@1 0.100→0.525, nDCG@10 0.317→0.719). Qwen3-Embedding is trained for last-token pooling. The wizard warns when it detects a Qwen3 model in a mean-pooling container (worse retrieval, not a crash); keep the warning.
- **`faiss_index_path(settings)` is a function in `config.py`, not a `Settings` attribute**; the benchmark originally called `settings.faiss_index_path` and crashed. Use the function.
- **Benchmark state**: `tests/retrieval_bench.py` must run in a fresh process per model/backend (FAISS and embed module globals leak otherwise). It writes a temp `SIMPLE_CI_CONFIG` and sets `WORKSPACE_ROOT`; `--local-path DIR` sets `INDEX_DB`/`FAISS_PATH` into `DIR` **after** the env overrides are cleared and re-derives the Qdrant collection from `DIR` too, so a run never touches a live workspace index or collection — `tests/bench_matrix.py` passes a per-run scratch folder under `artifacts/bench/<timestamp>/local/`, so every run gets its own collection. `QDRANT_COLLECTION` is still cleared with the other env overrides and cannot pin a collection; isolation comes from `--local-path`. `--reset` deletes `index.db*`, `vectors.faiss` (FAISS) or the derived Qdrant collection, and warns when it is about to hit `<workspace>/.simple-ci/index.db` because no `--local-path` was given. Existing embed containers both map host `8080`, so `tests/bench_matrix.py` stops the other one before starting the target. Reports land in `artifacts/`, which is `.gitignore`d and therefore no longer indexed.
- **Long benchmark runs need a background shell**: this harness caps a single `shell_command` at 10 minutes. Use `run_in_background=true` + `shell_output`/`shell_tasks` for the Nomic download and multi-model matrices.
- **Redirected home for live setup tests**: set `USERPROFILE`, `HOME`, `APPDATA`, and `LOCALAPPDATA` for the child process. `Path.home()` follows `USERPROFILE` on Windows; `install_root` reads `APPDATA`. `--install-dir` is the safest way to keep the real `%APPDATA%` untouched.
- **Uninstall is record-driven**: `setup.harnesses` (`{name, config}`) and `setup.install_root` in the global config are the only sources. Unrecorded harnesses are deliberately not scanned, so deleting `config.yaml` by hand leaves their entries behind. Removal is idempotent and also deletes the `<config>.bak.<YYYYmmdd-HHMMSS>` backups `write.install` created, then prunes emptied parent dirs up to home (`install.prune_empty_dirs`).
- **Removing a harness entry re-serializes JSON**: the same caveat as install — OpenCode `.jsonc` comments are lost on rewrite. Codex TOML removal only strips the `# >>> simple-code-indexer >>>` marker block, so the rest of the file (comments included) is untouched.
- **Uninstall compose cleanup only touches our compose file**: `docker compose -f ~/.simple-ci/docker/docker-compose.yml down --remove-orphans`, fail-soft when Docker is down. Externally managed containers and `--embedding-url` endpoints stay; workspace `<project>/.simple-ci/` indexes are never deleted.
- **A failed harness edit keeps `config.yaml`**: the record is needed to retry, so uninstall does not delete the config when any `write.remove` failed (exit code 1) — fix the malformed harness config and re-run. Only harness-edit failures count: a locked install copy or compose failure is fail-soft and still deletes the config. On Windows an install whose `.venv` is in use by a running harness cannot be fully removed; close the harness and re-run.
- **Uninstaller falls back to the real `%APPDATA%`** when no `install_root` is recorded, so tests MUST redirect `APPDATA`/`XDG_DATA_HOME` (`tests/test_uninstall.py` has an autouse fixture). A run without it tried to delete the developer's actual install (it failed only because the running server held the files).
- **Runtime logging is stderr INFO + `<workspace>/.simple-ci/log/sci.log` DEBUG** (`logging_setup.py`). The file handler sits on the **root** logger with a filter (`simple_code_indexer.*` at the configured level, every other logger at WARNING+) so `mcp` dispatch failures land in the file without `httpx`/`mcp` INFO spam. `configure_console()` gives the stderr handler its **own** INFO level — a plain `basicConfig(level=INFO)` leaves it at NOTSET, and propagated DEBUG records from the package logger would then print to stderr.
- **The log path follows `index_db_path.parent`**, so `INDEX_DB=/elsewhere/x.db` moves the log too; `Settings.log_level` (default `debug`) is file-only, stderr never goes below INFO. `logging_setup.configure_file` is fail-soft (unwritable dir → stderr warning, `get_status.log_file: null`), and `detach_file()` exists so tests never leave an open handle that breaks Windows `tmp_path` cleanup.
- **The package logger is pinned to DEBUG** by `configure_console()`; DEBUG records are then filtered by each handler (file: `log.level`, stderr: INFO). Do not raise the root logger instead — that would also let third-party DEBUG through and the file filter alone decides what is written.
- **`threading.excepthook` + `sys.excepthook` are chained, not replaced**: a dead daemon thread (`sweep-timer`, `watcher`, `index-writer`) is logged at CRITICAL with its traceback, and the previous hook still prints to stderr. `install_excepthooks()` is idempotent; tests that call the global hook must stub the previous one or pytest emits `PytestUnhandledThreadExceptionWarning`.
